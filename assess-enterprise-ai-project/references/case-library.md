## 案例使用规则

- 先评估当前项目，再读取相似案例。不得从案例反推当前项目一定通过或失败。
- 只迁移判断方法，不迁移用户、业务量、成本、模型效果、ROI、阈值、Owner 或项目结论。
- 明确区分 `脱敏真实案例` 与 `模拟案例`。模拟数据只能用于演示推理，不能描述为真实企业结果。
- 对真实案例默认删除公司名、客户名、人员名、内部系统名、合同价格、账号、原始会话和其他敏感信息。
- 保留已验证事实、文档主张、干系人主张、假设、未知和冲突之间的区别。材料自称“真实”或写出精确数字，不等于底层证据已经被独立核验。
- 将结论绑定到阶段和范围。`GO` 进入 POC、`GO` 进入 5% 灰度与 `GO` 全量上线是三个不同结论。
- 不为了让五门全部通过而美化材料。若案例源材料存在冲突，保留冲突并说明它是否会改变当前决策。
- 案例中写出的“预期结论”是该输入和范围下的参考判断，不是必须机械复制的标准答案。

## 案例规范

新增案例时使用以下结构。删除不适用的空字段，但不得省略决定最终结论的证据和失败门。

### 1. 案例元数据

| 字段 | 要求 |
|---|---|
| `case_id` | 使用稳定编号，例如 `CASE-001` |
| `case_type` | `脱敏真实案例` 或 `模拟案例` |
| `industry` | 行业与业务类型 |
| `decision_stage` | 当前阶段 → 申请阶段 |
| `decision_scope` | 用户、场景、节点、功能、自动化等级、渠道与预算范围 |
| `excluded_scope` | 明确不属于本次判断的部分 |
| `expected_decision` | 唯一的 `GO`、`VALIDATE-FIRST` 或 `NO-GO` |
| `evidence_status` | `SUFFICIENT`、`PARTIAL` 或 `INSUFFICIENT` |
| `confidence` | 高、中或低 |

### 2. 输入快照

用一段经过脱敏、可独立理解的文字模拟用户会提交的材料。只包含足以触发评估的信息，不把预期答案写进输入。

### 3. 来源与口径

列出来源类型、版本、适用范围和可靠性。真实案例至少说明：哪个来源负责数据口径，哪个来源只补充流程或方案；材料之间发生冲突时如何处理。

### 4. 证据摘要

只保留会改变五门状态或最终决策的证据：

| ID | 主张 | 证据类别 | 来源 | 对决策的影响 |
|---|---|---|---|---|

### 5. 五道门结果

| 决策门 | 状态 | 证据状态 | 置信度 | 关键判断 | 阻塞项或前置条件 | 一票否决 |
|---|---|---|---|---|---|---|

### 6. 决策合成

写明唯一结论、命中的决策规则、决定性证据、为什么不是另外两个结论，以及该结论不能外推到哪些范围。

### 7. 对应行动

- `GO`：给出获批阶段、范围、护栏、停止条件和下一复审点。
- `VALIDATE-FIRST`：给出可证伪假设、方法、样本、指标、阈值、Owner、周期、成本上限和停止条件。
- `NO-GO`：说明被否决的准确对象、决定性证据、替代方向和允许复评的条件。

### 8. 教学要点

总结该案例最值得复用的两到五条判断模式，并列出容易产生错误结论的做法。

## 案例一：美妆电商智能客服 V1.0

### 案例元数据

| 字段 | 内容 |
|---|---|
| `case_id` | `CASE-001` |
| `case_type` | 脱敏真实案例；依据用户提供的项目逐字稿和 PRD 重构 |
| `industry` | 美妆护肤、电商零售、智能客服 |
| `decision_stage` | 已完成 POC → 单一成熟渠道 5% 受控灰度 |
| `decision_scope` | 商品知识问答、基础售前导购、售后规则解释；高风险识别与转人工；先以 Copilot 验证，再开放低风险自动回复 |
| `excluded_scope` | 订单和物流实时查询；自动退款、赔付、改地址、补发；医疗判断；孕期、过敏不适、投诉等高风险自动处置；多渠道扩量和全量上线 |
| `expected_decision` | `GO / 应该做`：批准上述范围进入 5% 受控灰度 |
| `evidence_status` | `SUFFICIENT`，仅适用于该受控灰度决策 |
| `confidence` | 中；材料足以支持阶段性判断，但核心数字来自项目逐字稿，未在案例库中附原始日志和财务凭证 |

### 脱敏输入快照

> 某美妆电商企业希望评审智能客服 V1.0 是否可以从 POC 进入小流量灰度。企业有近三个月历史客服会话、商品资料、FAQ 和售后 SOP；现有客服需要人工判断问题、查找分散资料并组织回复，大促和直播时等待明显增加。一期计划只承接商品知识问答、基础售前导购和售后规则解释，高风险、低置信和强责任问题转人工。技术方案采用总控 Agent 负责风险识别与路由，三条固定 Workflow 执行业务任务，并组合规则、RAG、模型生成和输出审核。项目已完成离线评测和 Copilot 验证，希望先在一个成熟渠道开放 5% 低风险流量。

### 来源与数据口径

本案例依据以下私有材料形成，但不把原始材料打包进公开 skill：

| 来源 | 用途 | 本案例处理方式 |
|---|---|---|
| 项目逐字稿的最新汇总版本 | 项目数据、调研方法、技术评测、灰度结果和运营复盘口径 | 按用户要求作为数据主来源；重复出现且口径稳定的数据用于案例 |
| 电商智能客服 V1.0 一期 PRD | 产品范围、流程、AI 边界、技术架构、评测和兜底设计 | 只补充结构；数据与逐字稿不一致时不覆盖逐字稿 |

材料中的数字仍按来源性质标记。案例库没有附原始客服日志、评测明细和财务凭证，因此逐字稿与 PRD 中的结果统一标为 `documented_claim`，不标为 `verified_fact`，也不代表第三方审计结论。多份材料口径一致、当前审批范围有限且具备强护栏时，文档主张可以支持中置信度的阶段判断，但不能单独支持高置信度的规模化收益或红线事实。

以下冲突不静默合并：

- 逐字稿内出现约 `55%`、`160%` 和 `220%` 三种 ROI，以及 `6 个月`、`8 个月` 两种回收期；本案例不选择其中一个作为准确财务结果。
- 北极星指标在材料中出现“平均响应时间”和“AI 独立解决率”两种表达；本案例将两者作为 V1.0 的联合核心业务指标，要求在扩量前由业务负责人固定唯一北极星口径。
- 高风险指标同时使用“召回率”和“拦截率”表述；进入下一轮评审前必须统一分母、样本范围和误放行口径。

这些冲突会影响全量投资收益与扩量判断，但不会推翻“先进入单渠道 5% 受控灰度”的结论，因为本阶段投入和风险暴露被严格限制，且灰度本身用于获取真实业务、成本和安全证据。

### 一票否决检查

在本次范围内没有已证实的一票否决。该判断成立的原因不是“AI 很安全”，而是高风险与强责任任务已从自动化范围移除，并设置强制人工接管和停止开关。

若出现以下任一情况，立即停止自动回复或回滚到 Copilot / 人工：

- 隐私泄露、越权操作或退款赔付承诺。
- 使用后不适、孕期、医疗化、投诉等高风险问题未转人工。
- 无知识证据仍生成事实性回答，或引用过期、冲突知识。
- 核心指标跌破预设灰度基线，且短期内无法通过降级消除。

### 决策合成

**最终决策：`GO / 应该做`。批准美妆电商智能客服 V1.0 的三个低风险业务工作流，从已完成 POC 进入单一成熟渠道、5% 流量的受控灰度。**

- 命中规则：当前申请阶段要求的五门均通过；没有适用于该范围的一票否决；剩余不确定性可在严格限流和可回滚条件下观察，不改变是否开始本次受控灰度。
- 决定性证据：E01-E08 共同证明真需求、AI 增量价值、技术可行性和安全运营路径；E09 限制后续扩量，但不否决本次限额灰度。
- 为什么不是 `VALIDATE-FIRST`：关键技术假设已通过离线评测与 Copilot 验证；当前申请本身就是可回滚的真实流量验证阶段，不需要在进入该阶段前再复制一次同类 POC。
- 为什么不是 `NO-GO`：需求高频且有损失，AI 只承担其更擅长的语义理解和证据生成节点，权限、高风险和确定性决策已交给规则或人工，没有已证实致命障碍。
- 禁止外推：本结论不批准订单/物流工具调用、自动退款赔付、多渠道扩量或全量上线，也不证明某个精确 ROI 已成立。

### GO 后的行动与复审点

| 项目 | 要求 |
|---|---|
| 获批范围 | 单一成熟渠道的 5% 低风险会话；仅商品知识问答、基础导购和售后规则解释 |
| 上线方式 | Copilot 已通过后再开放自动回复；所有高风险、低置信、无证据和规则冲突转人工 |
| 质量护栏 | 一级意图识别、RAG、商品问答和高风险指标不得跌破预先冻结的灰度准入线 |
| 红线 | 隐私泄露、越权承诺、医疗化误导、高风险误放行和无证据自由生成均按 P0 处理 |
| 监控 | 同时观察 AI 独立解决率、首响、转人工原因、客服反馈、知识冲突、成本和 P0/P1 Bad Case |
| 运营 | 每日抽检，周度由产品、算法、研发、客服运营和合规复盘；所有 P0 当天止损 |
| 回滚 | 命中红线或质量持续低于准入线时，停止自动回复并降级为 Copilot、模板或人工 |
| 下一复审点 | 完成首个 5% 灰度周期后，使用真实流量重新评估是否扩大流量或渠道 |
| 扩量前必补证据 | 唯一北极星口径、高风险指标口径、真实采用率、人工接管容量、完整 TCO、可兑现收益和统一 ROI/回收期 |

### 教学要点

1. **把“项目值得做”改写成阶段性、范围受限的决策。** 本案例通过的是三个低风险流程进入 5% 灰度，不是全能客服全量上线。
2. **第二门先拆规则、人工和 AI。** 模型负责开放语言理解和基于证据的表达；规则负责确定性与权限控制；人工负责高风险和强责任判断。
3. **第三门输出技术组合而不是单选标签。** 本案例不是在 RAG、Agent、Workflow 中三选一，而是由它们承担不同职责。
4. **有冲突的数据不静默选优。** 多版 ROI 不影响受控灰度，但会阻止用该数字批准全量投资。
5. **GO 不等于没有风险。** 风险通过缩小范围、Copilot、人工接管、限流、监控和回滚被控制在当前阶段可接受范围内。

容易犯的错误：

- 因为项目最终上线过，就倒推五道门一定全部通过。
- 把逐字稿中所有数字都视为互相一致的审计事实。
- 将 V1.0 的知识问答证据用于证明 V2.0 订单和物流 Agent 可行。
- 只写“RAG + Agent”，不解释规则、模板、人工和各组件职责。
- 用整体准确率掩盖高风险误放行，或把正确转人工算成 AI 独立解决。

### 脱敏输入快照

> 某美妆电商品牌计划评审一款“品牌营销 AIGC 内容增长 Copilot”。内容团队认为现有生产方式耗时，直接使用通用大模型时又经常出现“不像品牌”“不像真实用户分享”“产品卖点失真”和效果不稳定。方案拟先选择小红书种草文案：拆解历史高表现内容中的受众、使用场景、核心卖点、内容结构和表达方式，再结合本品牌商品资料、品牌语气和合规要求生成草稿，由编辑审核后发布。管理者希望未来沉淀为覆盖多渠道、多模态和多个团队的企业级 AIGC 平台，但尚未提交一线访谈、任务日志、内容基线、模型对照、业务增量、完整成本及运营责任材料。

本案例评估的不是“AI 能不能写文案”，而是：**在一个边界明确的美妆内容节点中，加入内容结构拆解、品牌与商品知识、确定性规则和人工审核后，是否比人工现状、通用大模型和采购工具产生可归因的增量价值。**

### 第二门的范围收敛

#### 当前流程假设 `AS-IS`

`接收商品与活动 Brief → 搜集参考内容 → 提炼卖点与人群 → 撰写初稿 → 品牌/法务审核 → 修改 → 发布 → 查看表现`

该流程只是待验证假设。正式评估必须通过一线访谈、任务观察或操作记录补充等待、返工、工具切换、异常路径和各节点基线。

#### 规则、人工与 AI 分工

| 节点 | 推荐执行者 | 原因与边界 |
|---|---|---|
| Brief 字段完整性、必填格式和禁用词预检 | 规则 | 条件明确、可枚举、结果需要确定性 |
| 历史内容结构拆解和候选卖点表达 | AI 辅助 | 输入非结构化、表达变化大，但“高表现原因”只能作为假设，不能由模型宣称因果 |
| 根据品牌、商品和渠道约束生成多个草稿 | AI 辅助 | 适合受约束生成；商品事实必须来自授权资料，未知事实不得补写 |
| 广告法高风险词、绝对化用语、必带声明和格式 | 规则优先 | 可枚举红线不交给模型自由判断；规则未覆盖项再交人工 |
| 品牌一致性、创意取舍和是否发布 | 人工 | 属于主观判断与品牌责任，POC 阶段不授权 AI 自动发布 |
| 发布排期、账号操作和投放预算 | 现有工具或人工 | 不属于本次内容生成问题，不因平台设想扩大 AI 权限 |
| 发布后的数据分析与反馈归类 | 规则统计 + AI 辅助总结 + 人工判断 | 指标计算保持确定性；AI 可归纳反馈，业务人员决定是否调整策略 |

交给第三门的最小 AI 节点只有两个：`内容结构拆解` 与 `受品牌和商品事实约束的草稿生成`。如果规则模板或采购工具在同条件下已经达到业务目标，应停止自研 AI 方案。

### 第三门的候选技术方案

| 组件 | 当前职责 | 为什么纳入或排除 |
|---|---|---|
| Workflow | 固定编排 Brief 校验、知识获取、结构拆解、草稿生成、规则校验和人工终审 | 流程稳定且需要审计，优先使用确定性编排 |
| 品牌/商品知识检索 | 提供经授权的商品事实、品牌语气、渠道规范和有效版本 | 防止模型凭记忆补写事实；需验证知识完整性、更新及时性和引用准确性 |
| AIGC 大模型 | 承担非结构化拆解、候选表达和受约束草稿生成 | 需要在相同测试集上比较质量、延迟、成本、数据策略和稳定性 |
| 规则引擎 | 校验禁用表达、必要字段、格式和部分广告法红线 | 确定性红线不能只依赖提示词或模型自检 |
| 人工工作台 | 展示来源、风险提示和版本差异，由编辑修改、采用、拒绝并记录原因 | 保留发布责任，同时产生采用率、编辑时长和 Bad Case 数据 |
| Agent | 暂不纳入 | 当前步骤和工具可预先定义，没有需要动态规划的证据；引入 Agent 只会增加成本和不可控性 |

不得预设某个模型必然胜出。候选模型必须在同一 Brief、知识源、Prompt、规则和评分标准下比较；公开榜单和供应商演示只用于筛选候选，不用于得出可行性结论。

### 一票否决检查

当前没有证据充分的一票否决，但验证期间必须重点排查以下红线：

- 未经授权使用达人、用户或竞品内容，生成与原文高度相似的内容，且无法通过授权、引用、去重或范围收缩解决。
- 捏造商品成分、功效、适用人群或真实使用体验，或者严重违规表达无法被规则和人工终审可靠拦截。
- 将 AI 包装成真实消费者或特定达人，造成身份误导。
- 企业拒绝保留人工发布权、追溯日志或停止开关，要求系统自动批量发布。
- 品牌、商品和历史内容数据没有合法、稳定的使用与更新路径。

在这些情况被验证前，只能标记为待验证风险，不能把怀疑写成已触发否决。

### 决策合成

**最终决策：`VALIDATE-FIRST / 应该先验证`。不批准企业级 AIGC 平台或正式产品 POC 建设；仅允许执行下面的限时、限额验证，验证对象限定为一个美妆品牌、一个渠道和一种种草文案。**

- 命中规则：第一、二、三、五门为 `CONDITIONAL`，第四门为 `NOT-ASSESSABLE`；关键未知会改变需求、技术路线、投资方式和运营负担，但能够通过低成本实验获取证据。
- 决定性证据：E01-E05 说明需求和技术组合存在合理成立可能；E06-E08 说明现有目标值和方案文档不能证明业务采用、AI 增量、技术效果或 ROI。
- 为什么不是 `GO`：尚无目标企业的一线流程、业务基线、同条件对照、代表性评测、完整成本和 Owner 承诺，剩余事项会直接改变是否立项，而不是普通执行项。
- 为什么不是 `NO-GO`：目前没有经验证的致命负面证据；生成草稿属于低权限、可人工复核、可停止的节点，能够用有限成本安全验证。
- 禁止外推：即使单场景验证通过，也不批准多品牌、多渠道、多模态、自动发布或企业级平台建设；每次扩大范围都要重新跑五道门。

### 最低成本验证计划

以下样本、阈值和成本上限均为**模拟案例中的实验设计值**，不是行业标准或历史结果。真实使用时必须由业务负责人、内容负责人、合规负责人和财务在看到结果前共同冻结。

#### 验证一：真需求与业务基线

| 字段 | 设计 |
|---|---|
| `hypothesis` | 目标内容团队存在高频、可重复且损失可测的内容生产瓶颈，问题主要集中在资料理解、结构组织和品牌化初稿，而不是审批排队或 Brief 缺失 |
| `method` | 访谈与任务观察结合；核对内容排期、修改记录和已发布内容，不只询问管理者 |
| `scope` | 访谈 6 名内容编辑/运营，观察或回溯不少于 30 个同渠道种草任务；排除纯视觉创作、达人商务和投放决策 |
| `metrics` | 周任务量、端到端时长、初稿时长、修改轮次、返工原因、现有 AI 工具使用率、一次采用率及延误数量 |
| `pass_threshold` | 至少 4/6 名一线人员和任务记录指向同一核心瓶颈；不少于 50% 样本属于可重复的目标任务；问题节点贡献至少 30% 的端到端人工时长 |
| `stop_condition` | 主要损失被证实来自审批、素材缺失或跨部门等待，且生成环节不是主要瓶颈；或目标任务量不足以支持持续使用 |
| `owner` | 品牌内容负责人对业务口径负责，AI 产品经理对调研和证据台账负责 |
| `duration` | 5 个工作日 |
| `cost_cap` | 不开发系统；最多投入 1 名 AI 产品经理和 1 名内容运营的各 5 人日 |
| `next_decision` | 通过则冻结基线并进入验证二；未通过则停止当前 AI 节点，转做流程、Brief 或审批优化；证据冲突则补充定向观察 |

#### 验证二：AI 增量与技术可行性

| 字段 | 设计 |
|---|---|
| `hypothesis` | “结构拆解 + 品牌/商品知识 + 规则审核”的垂直方案，相比直接使用通用大模型，能显著提高可用性和品牌一致性，同时控制事实与合规风险 |
| `method` | 使用同一批真实历史 Brief 做盲评对照：A 为人工历史稿，B 为通用大模型直接生成，C 为候选垂直方案；记录所有输入、输出、知识版本和失败类型 |
| `scope` | 40 个经过授权并脱敏的 Brief，覆盖不少于 3 类商品或生命周期场景；每个 Brief 生成 A/B/C 三组结果，由 3 名编辑独立盲评；另建广告法、虚假功效和事实冲突红队样本 |
| `metrics` | 首轮可用率、品牌一致性、商品事实正确性、严重违规漏放、内容相似风险、生成延迟、单次生成成本和四类失败模式 |
| `pass_threshold` | C 组首轮可用率比 B 组至少提升 15 个百分点；品牌一致性平均不低于 4/5；正常样本商品事实正确率不低于 98%；红队样本不得出现严重违规漏放；成本和延迟不超过实验前冻结上限 |
| `stop_condition` | C 组对 B 组没有稳定增量；发生无法通过知识、规则或人工终审控制的严重事实、版权或合规问题；必要数据无法合法使用 |
| `owner` | AI 产品经理负责实验设计，算法/工程负责人负责技术复现，内容与合规负责人负责盲评和红线判定 |
| `duration` | 10 个工作日 |
| `cost_cap` | 不建设平台、不微调模型；复用现成模型 API 和轻量原型，最多投入产品 5 人日、工程/算法 10 人日、内容与合规各 3 人日，外部 API 现金支出上限 3000 元 |
| `next_decision` | 通过则进入验证三；未通过则停止当前自研组合并评估规则模板或采购工具；局部失败可移除时仅重测缩小范围 |

#### 验证三：业务采用、单位经济性与运营承载

| 字段 | 设计 |
|---|---|
| `hypothesis` | 编辑在真实任务中愿意持续使用该方案，节省的时间能够转化为可兑现的增产或外包减少，且审核和维护负担不会吃掉收益 |
| `method` | 用轻量原型或 Wizard of Oz 完成两周受控试用；记录生成、编辑、采用、拒绝、审核、发布、成本和 Bad Case，并与验证一基线比较 |
| `scope` | 4 名内容编辑、不少于 50 个真实任务；仅生成草稿，全部人工终审；业务效果只作为观察指标，不用短期“爆款率”单独决定立项 |
| `metrics` | 草稿采用率、平均编辑时长、端到端时长、拒绝原因、审核负担、每条可用内容总成本、P0/P1 事件，以及发布率、互动和转化的方向性表现 |
| `pass_threshold` | 草稿采用率不低于 60%；目标节点中位处理时长比基线下降至少 30%；每条可用内容总成本不高于人工基线的 80%；没有 P0 事实、版权或合规事件；人工审核量不超过内容团队预先承诺容量 |
| `stop_condition` | 经过一次可解释迭代后采用率仍低于 30%；端到端时间没有下降；总成本不低于基线；出现 P0 事件或审核团队无法承载 |
| `owner` | 品牌业务负责人对采用和收益兑现负责，内容负责人对审核容量负责，财务确认成本口径，合规负责人拥有停止权 |
| `duration` | 10 个工作日，结束后 2 个工作日内复审 |
| `cost_cap` | 不接自动发布、不新增渠道；沿用验证二原型，新增投入最多产品 3 人日、工程 3 人日、内容审核 8 人日，现金支出累计仍不得突破预先批准的实验预算 |
| `next_decision` | 三项关键阈值均通过且五门补证后，重新评审是否 `GO` 进入正式 POC；任一停止条件命中则对当前方案 `NO-GO`；结果不稳定则只延长对应分群验证，不扩大范围 |

### ROI 验证口径

验证前只建立变量和收益链，不填写虚构的财务结果：

- `可兑现收益 =（可归因的增产收益 + 可减少的外包支出 + 可兑现的人力节省）× 采用率 × 业务兑现率`
- `每条可用内容总成本 =（原型与集成摊销 + 模型调用 + 知识维护 + 生成失败 + 编辑修改 + 合规审核 + 运营治理 + 预期风险损失）÷ 实际采用内容数`
- `净收益 = 可兑现收益 - TCO`

互动率、点击率和转化率受选品、价格、投放、账号、活动和季节影响。若要主张内容带来增收，必须使用随机或匹配对照、固定其他变量并说明归因限制；不能用一篇偶然高表现内容证明系统能够复制爆款。

### 验证后的平台化路线

单场景通过不等于应该建设平台。只有当多个已验证场景反复需要相同的 Brief 解析、品牌/商品知识、Prompt 与 Workflow 管理、模型路由、规则审核、人工工作台、评测监控和成本治理能力时，才把这些共性能力作为新的决策对象评估平台化。

平台化评审必须重新证明：复用收益高于平台抽象和迁移成本、各团队愿意采用、权限和数据能够隔离、持续运营责任明确。图片、视频、代码生成和浏览器插件等能力不得因为出现在方案文档中自动进入范围。

### 教学要点

1. **行业相关不等于范围越大越好。** 用单品牌、单渠道、单内容类型呈现业务深度，再用平台化路线呈现架构视野。
2. **把“爆款复制”改写成可验证的问题。** 项目验证的是结构迁移、品牌一致性、内容采用和单位经济性，不承诺制造爆款，也不把相关性写成因果。
3. **第二门先决定分工。** AI 负责非结构化拆解和候选生成；规则负责确定性红线；人工拥有品牌取舍和发布权。
4. **第三门用组合方案并做公平对照。** 固定流程优先 Workflow，不因“更高级”而加入 Agent；同时比较人工、通用模型、垂直方案和采购替代。
5. **平台目标不能冒充企业证据。** 采用率、延迟、成本和合规率在未说明口径、基线和实验结果前，只是目标或假设。
6. **Vibe Coding 的价值来自可运行验证闭环。** 轻量原型、评测记录、证据台账和停止条件比一次性搭建大平台更能证明 AI 产品落地能力。

容易犯的错误：

- 把生成量、速度或文案流畅度当成业务价值。
- 只与纯人工比较，不与通用大模型、现成 SaaS、规则模板和流程优化比较。
- 用模型自评品牌感和合规性，不保留编辑盲评、规则检查及合规停止权。
- 忽略修改、审核、知识维护和失败内容成本，得到虚高 ROI。
- 因单个美妆场景通过，就直接批准多品牌、多渠道、多模态平台。

## 案例三：跨平台全自动广告投放 Agent

### 脱敏输入快照

> 某消费品牌在四个广告平台运营六个账户，五名投手平均每天完成约 180 次预算、出价、启停和素材调整。八周操作日志显示，投手每天约有四小时用于查看报表、解释波动和执行重复调整，大促期间容易错过处理窗口。团队完成了一个离线 Agent POC：系统每 30 分钟汇总平台数据，根据投放目标自主选择动作，并计划获得跨账户写权限，在生产环境自动调整预算和出价、暂停或新建计划。
>
> 公司现行资金与广告账户制度规定，单日预算变化超过 1 万元或跨账户调拨必须由账户负责人和业务负责人双重确认。项目方认为逐次确认会损失自动化价值，坚持生产方案不设置人工审批。技术评审确认，当前广告 API 只能授予账户级写权限，无法按 Agent 单次动作细分授权；系统可以停止未来动作，但已经消耗的广告预算不能原子回滚。离线 POC 在预先冻结的 300 个历史决策窗口中，动作方向总体正确率为 91%，但产生 11 次 P0 严重动作，包括在归因回传延迟时错误加大预算、跨账户调拨和暂停仍有价值的计划；POC 的 P0 准入阈值为 0 次。

本案例的关键不是“Agent 是否足够聪明”，而是：**一个存在真实提效需求的场景，是否可以把不可逆的资金与经营动作交给不具备责任主体资格、且已超过严重失败阈值的 AI 独立执行。**

### 来源与数据口径

### 一票否决与失败链

本案例的 `NO-GO` 由三条相互独立、证据充分的失败链支持：

1. **权限失败**：E02 + E03 证明公司制度要求双重授权，而当前方案把最终预算权交给 Agent，并明确拒绝人工确认。
2. **能力与技术失败**：E04 + E05 证明系统在冻结样本上已经超过 P0 停止阈值，且错误与归因延迟和跨平台口径差异有关，不是偶发的文案瑕疵。
3. **运营与恢复失败**：E06 证明权限不能细分、已发生花费不能回滚；停止未来动作不等于消除当前错误后果。

其中任意一条已证实的一票否决都足以否决当前范围，不需要等待 ROI、平均准确率或更多功能完成。第一门通过只证明问题值得解决，不证明当前 Agent 自动化方案值得做。

### 决策合成

**最终决策：`NO-GO / 不应该做`。否决 Agent 在多个广告平台和账户中、未经逐次人工确认，直接调整预算和出价、启停或新建计划的生产自动执行方案。**

- 命中规则：第二、三、五门均有 `FAIL`，并触发适用于当前范围且证据充分的一票否决；验证结果也已低于实验前冻结的 P0 停止阈值。
- 决定性证据：E02-E06 共同证明权限制度冲突、严重失败已发生、关键输入不完整、写权限过宽且损失不可完整回滚。
- 为什么不是 `GO`：真实需求和潜在提效不能抵消权限、安全和运营失败；总体 91% 正确率不满足资金动作的严重失败标准。
- 为什么不是 `VALIDATE-FIRST`：这不是“还缺一次实验”。当前方案已经在冻结样本上命中停止条件，且项目方拒绝加入能够改变风险结构的人工审批；继续扩大同一方案的测试没有立项意义。
- 禁止外推：本结论不等于否决广告投放 AI、异常检测、智能分析、素材生成、预测模型或投放 Copilot，也不证明所有低额度自动规则都不可行。

### NO-GO 后的对应行动

#### 被否决的准确对象

停止为当前 Agent 申请跨账户生产写权限，不进入真实预算灰度，不以“先小流量上线再观察”绕过 P0 停止线。保留离线日志用于复盘，不把失败结果删除或重新定义为普通 Bad Case。

#### 可行替代方向

将替代方案定义为新的评估对象，而不是原方案的“有条件通过”：

| 节点 | 建议分工 | 自动化等级 |
|---|---|---|
| 数据汇总、异常发现和变化解释 | 确定性统计 + AI 辅助归纳 | 只读 |
| 优化机会排序和动作草案 | 预测模型/规则 + AI 建议 | Copilot，不写入账户 |
| 预算上限、账户权限、动作白名单和跨账户限制 | 规则与权限系统 | 硬约束，不允许模型绕过 |
| 预算、出价、启停和新建计划 | 有权限的投手或双重审批人 | 人工确认后执行 |
| 执行、日志和效果回收 | Workflow + 广告平台 API | 只执行已批准动作，全程审计 |

新的“投放优化 Copilot + 人工确认 + 规则护栏”方案应先按 `VALIDATE-FIRST` 重新跑五道门，不能沿用全自动 Agent 的模型结果、成本或结论。

#### 允许重新评估当前自动执行范围的条件

只有以下条件全部发生实质变化，才允许将自动执行作为新版本重新提交，而不是继续原方案：

- 公司制度明确授权某类低风险、限额动作由系统执行，并定义责任主体；需要双重审批的动作仍不得自动化。
- API 或中间控制层能够落实最小权限、账户与动作白名单、单次和累计额度、频率限制及双重确认。
- 数据治理解决关键指标的时间窗、口径和回传状态问题，系统能够识别数据未成熟并拒绝执行。
- 新版本在重新冻结的代表性样本与红队场景中满足 P0 为 0 的准入线，同时报告拒绝、漏做、误做和越权，不只报告平均正确率。
- 完成影子运行、人工对照、低额度可回滚演练和事故响应演练，并证明审核、告警、停止与审计责任真实可用。
- 风险调整后的 TCO、净收益和最坏情景达到企业预算与损失承受门槛。

满足这些条件也只代表可以重新评审，不自动获得 `GO`。

### 教学要点

1. **真需求通过，不代表当前 AI 方案通过。** 本案例保留投放提效需求，只否决错误的自动化等级和权限配置。
2. **AI 能提出动作，不代表 AI 有权执行动作。** 资金、预算和跨账户调拨属于权限边界，模型准确率不能授予制度权限。
3. **严重失败优先于平均指标。** 91% 总体正确率不能覆盖 11 次 P0；评测必须同时报告平均质量和不可接受失败。
4. **停止开关不等于回滚。** 它可以阻止下一次调用，却不能追回已经消耗的预算或完全恢复被误停计划的机会损失。
5. **`NO-GO` 必须有已验证负面证据。** 缺材料只会导向补证；本案例因为制度、实验结果和技术限制均已确认，才作确定否决。
6. **替代方案是新的决策对象。** Copilot、规则护栏和人工审批值得验证，但不能被写成全自动 Agent 已经有条件通过。

容易犯的错误：

- 因为人工流程低效，就默认自动执行是唯一正确方案。
- 用总体正确率、平均 ROI 或最佳案例掩盖 P0 和尾部损失。
- 把“日志可查”和“能停止后续动作”误写成“发生错误后可回滚”。
- 把人工确认视为产品失败，而不是高风险流程中必要的责任机制。
- 因替代方案可能成立，就把当前被否决范围改写为 `VALIDATE-FIRST`。
