# 企业 AI 项目五道门评审

## 1. 执行结论

| 项目 | 当前阶段 → 申请阶段 | 评估模式 | 决策 | 总体证据状态 | 置信度 |
|---|---|---|---|---|---|
| 电商跨渠道全自动定价 Agent | 离线历史回放 → 全渠道生产自动执行 | 完整评估 | `NO-GO / 不应该做` | `SUFFICIENT`（用于否决当前范围） | 高 |

- 决策对象：是否授予 Agent 三个自营渠道、约 8,000 个 SKU 的生产写权限，使其未经逐次人工确认即可调整价格、折扣和活动？
- 否决范围：跨三个渠道、覆盖约 8,000 个 SKU、无人工确认并直接写入价格和活动的全自动执行方案。
- 排除项：本结论不否决定价需求本身，也不否决只读分析、异常预警、定价 Copilot、确定性毛利规则或人工审批后执行。
- 一句话判断：当前方案与有效定价制度冲突，在冻结回放中出现 9 次 P0，且权限过宽、数据延迟、结果不可完整回滚、无人承担最终业务责任，已经具备多条独立的否决证据。
- 唯一下一步：停止申请全部 8,000 个 SKU 的生产写权限，不进入“先全量一周再观察”。

> 证据说明：当前只读取了模拟测试项目汇总材料，没有直接打开其中提到的政策原件、500 条逐条回放记录和 API 评审附件，因此具体主张标记为 `documented_claim`。该测试材料明确将制度、评测口径和限制设定为当前有效且相互一致，足以对高风险、全量生产申请作出否决；真实企业评审仍应归档原件。

## 4. 逐门判断

### 第一门：真需求判断

需求本身成立：调价工作高频，人工分析和执行耗时，峰值期存在响应延误。根因包括数据分散、异常发现慢和重复操作。因此不能把当前方案失败误写成“企业不需要改进定价流程”。

### 第二门：AI 必要性与业务分工

| 节点 | 应由谁负责 | 原因 |
|---|---|---|
| 数据汇总、异常识别和机会解释 | BI/统计 + AI 辅助 | AI 可以处理复杂模式和解释，但保持只读 |
| 动作建议与情景测算 | 规则/预测模型 + AI Copilot | 可以提高决策效率，不取得授权权力 |
| 毛利底线、变动幅度、SKU 白名单和活动资格 | 确定性规则与权限系统 | 属于不可由提示词替代的硬约束 |
| 大幅调价、跨渠道同步和最终执行 | 有权限的商品负责人及财务 | 现行制度要求双重确认 |
| API 执行与审计 | 固定 Workflow | 只执行已批准动作，保留完整日志 |

当前方案把权限性最终决策交给 Agent，并把拒绝人工审批定义为核心价值，第二门因此 `FAIL`。

### 第三门：AI 技术选型与可行性验证

- 冻结的 P0 准入线为 0，实际出现 9 次；提示词迭代后仍重复 5 次。
- 94.2% 是平均动作方向正确率，不能抵消突破毛利、绕过审批、错误参加活动和跨渠道冲突等不可接受失败。
- 6 次 P0 与数据未稳定或优惠口径不一致有关，说明仅调整提示词不能解决信息边界。
- 店铺级写权限无法限制到 SKU、变动幅度或毛利区间；已成交订单和部分活动影响不可原子回滚。

这不是尚未完成普通工程工作的 `CONDITIONAL`，而是当前技术和权限组合已经在代表性回放中低于停止阈值，因此第三门 `FAIL`。

### 第四门：阶段投资合理性与规模化 ROI

- `stage_investment_status: FAIL`（针对当前全量生产申请）：没有低权限影子运行、SKU 白名单、额度和损失上限，计划直接全量一周收集数据，不具备可接受的实验损失边界。
- `scale_roi_status: NOT-ASSESSABLE`：4.2 人力只是工时折算，没有减员、外包取消或新增承载计划；200 万元毛利没有对照或因果测算；P0 损失、补贴、客诉、处罚、品牌价格体系破坏和事故成本均未计入。
- 第四门整体针对当前“直接全量生产”申请为 `FAIL`：本阶段投入本身不具备可接受的风险边界；规模化 ROI 仍为 `NOT-ASSESSABLE`。本门不是唯一否决依据，也不能覆盖已证实的权限、技术和运营否决。

### 第五门：运营、数据与兜底

不存在愿意承担无人值守定价责任的业务 Owner；监控按小时汇总，无法适配大促期间快速积累的不可逆订单；总停止开关只能阻止未来动作，不能恢复已经成交的价格和活动损失；白名单、幅度、累计损失和双重审批均缺失。第五门 `FAIL`。

## 5. 一票否决与决策合成

至少三条相互独立的否决链成立：

1. 权限制度要求双重确认，但当前方案拒绝人工审批；
2. 9 次 P0 超过实验前冻结的 0 次准入线；
3. 高风险写权限无法细分，已发生价格和活动损失无法可靠回滚，且无人承担最终业务责任。

为什么不是 `VALIDATE-FIRST`：当前方案不是单纯缺少数据，而是已经命中预设停止条件，并拒绝加入会改变风险结构的人工审批和权限限制。继续把同一方案放入真实全量环境不会提供合理的新证据，只会扩大风险。

为什么不是 `GO`：真实需求、94.2% 的平均方向正确率和潜在收益都不能抵消权限、P0 和不可恢复损失。

## 6. 下一步：停止当前决策对象

- 立即停止：申请三个渠道、约 8,000 SKU 的全量生产写权限，以及“先全量一周再观察”的计划。
- 可保留资产：业务日志、数据口径问题清单、500 个回放窗口、P0 定义和失败样本。
- 可作为新决策对象：`只读定价分析/定价 Copilot + 毛利与额度规则 + 人工双重确认 + 固定 Workflow 执行`。
- 重新评估条件：制度授权明确；最小权限、SKU 白名单、幅度和累计额度可落实；数据成熟度和跨渠道口径可识别；重新冻结测试集中 P0 为 0；完成影子运行和事故演练；风险调整后的本阶段投入与规模化经济性达到企业门槛。

替代 Copilot 是新的评估对象，不能把它写成当前全自动 Agent 已转为 `VALIDATE-FIRST`。
