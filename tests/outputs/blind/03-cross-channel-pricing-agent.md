## 6. 第三门：AI技术选型与可行性

- **状态**：FAIL
- **一句话判断**：离线回放已经证明当前 Agent 方案不能满足其自定的生产安全阈值。

### 评测判断

- 样本：500 个历史决策窗口，覆盖六类主要场景。
- 预设阈值：建议方向正确率不低于 90%，P0 必须为 0。
- 结果：方向正确率 94.2%，但出现 9 次 P0，即 500 个窗口中的 P0 发生比例为 1.8%。
- 其中包括突破毛利底线、绕过审批、错误参加活动和跨渠道价格冲突。
- 提示词加约束后，原 9 次 P0 中仍有 5 次复现，表明问题不能依靠提示词可靠消除。

### 生产约束

| 约束 | 当前证据 | 判断 |
|---|---|---|
| 实时数据 | 竞品价延迟，退款及补贴数据需 24–72 小时稳定 | 不满足实时自动决策的完整性要求 |
| 渠道口径 | 折扣、券、补贴及最低成交价口径不一致 | 必须先做确定性标准化 |
| 最小权限 | API 只能授予店铺级价格写权限 | 不达标 |
| 风险限制 | 无 SKU 白名单、价格幅度及损失上限 | 不达标 |
| 严重错误 | P0=9，要求为0 | 不达标 |
| 回滚 | 已成交订单及部分活动损失无法恢复 | 不达标 |
| 监控 | 每小时汇总；高峰期一小时内可形成大量订单 | 响应速度不足 |

因此触发第三门两项否决：严重失败超过不可降低阈值；高风险操作无法被充分限制、人工接管和可靠恢复。
