## 4. 分门评审

### 第一门：真需求判断

核心判断链为：

`三类目标用户 → 每季开展趋势研究 → 浏览多源材料并制作主题板 → 管理者称周期为两至三周 → 具体痛点和根因未知 → 损失未知 → 三项笼统收益 → 北极星指标未知`

判断：

- 目标用户、季度触发场景、当前任务和粗略周期已提出，足以形成待验证需求。
- 需求证据仅来自一份管理层访谈纪要，没有实际执行者、流程观察或行为记录。
- 尚不能判断两至三周是否异常、最耗时节点在哪里，或周期长是否主要由审批、协作、数据质量、创意探索等非AI因素造成。
- “提高命中率、减少滞销”没有定义，且趋势判断与最终销售之间存在多项已知混杂因素。

通过条件：由实际用户确认至少一个可观察、可测量、值得解决且项目能够影响的节点，并确定一个结果指标及相应质量护栏。

### 第二门：AI必要性与业务分工

现有材料只能支持候选分工，不能支持正式结论：

| 候选节点 | 当前可支持的局部判断 | 不能确认的事项 |
|---|---|---|
| 数据清单、编码映射、权限和质量治理 | 更偏向数据治理、规则及人工责任 | AI无法替代缺失的授权和主数据治理 |
| 销量、搜索行为分析 | 统计或传统预测是必要对照 | AI是否有增量优势未知 |
| 文本、图片趋势归类 | 多模态AI可能适配 | 业务量、质量标准和非AI替代方案未知 |
| 品牌资料检索 | 检索可能有用 | 知识范围、版本和更新责任未知 |
| 灵感图及说明草稿 | AIGC可能适配，且应由设计师审核 | 可用性、品牌一致性、相似性和审核成本未知 |
| 选款、打样 | 应保留人工 | 具体审核与责任流程未定义 |

正式 POC 前必须把“预测、聚类、检索、生成”拆成独立节点，分别比较规则、人工、BI、传统模型、采购工具和AI。当前不能把整条流程整体认定为AI场景。

### 第三门：技术选型与可行性验证

以下进入 POC 所需条件全部缺失：

- 明确的AI节点输入、输出和允许错误；
- 可合法使用的数据及代表性样本来源；
- 历史回测窗口、时间切分和防泄漏方案；
- 非AI基线和同条件模型比较；
- 总体、关键分群和严重失败阈值；
- 编码映射与销售混杂因素处理方案；
- 版权、相似性、品牌一致性及数据处置要求；
- 集成、权限、日志、降级和停止机制。

技术风险尚未被证实为不可解决，所以不能判 `FAIL`；但也没有足够规格批准正式 POC。

### 第四门：阶段投资合理性与规模化ROI

- `stage_investment_status：NOT-ASSESSABLE`
- `scale_roi_status：NOT-ASSESSABLE`

30万元只是预算申请值，不是已验证的合理成本上限。当前无法回答：

- 30万元将购买哪些决策证据；
- 失败时最多损失多少、何时停止；
- 哪些时间节省能转化为产能、外购费用下降或其他财务价值；
- 设计采用如何影响上市商品，再如何与销售、库存和折扣结果归因；
- 持续模型、数据、审核、法务和运营成本是多少。

后续经济模型至少应遵循：

`可兑现收益 = 理论收益 × 实际采用率 × 业务兑现率`

`TCO = 一次性投入 + 持续成本 + 预期风险损失`

现阶段不能计算净收益、ROI或回收期，也不能将“缩短研究周期”直接视为节省人力成本。

### 第五门：运营、数据与兜底

申请进入 POC 所需的最低治理条件尚未落实：

- 已具名且有权限的实验业务Owner；
- 数据Owner和书面授权；
- 人工监督者及审查规则；
- 模型、数据或输出异常时的停止开关；
- 实验数据、提示词和生成内容的保留及删除规则。

“最终人工决策”只说明了自动化边界，不能代替版权审核、品牌审核、人工容量、异常处置和责任追溯方案。

| 验证结果 | 后续处理 |
|---|---|
| 三项均达到预注册阈值 | 重新评审一个缩小、单节点、人工确认型的正式 POC；不自动批准原始全范围 POC |
| 真需求成立，但AI未优于非AI基线 | 停止当前AI节点，单独评估流程优化、BI、传统预测或采购方案 |
| 数据或版权路径不成立 | 停止受影响的数据源或生成节点；不得以“公开可见”代替使用授权 |
| 技术有效但无法落实Owner、审核或停止机制 | 不进入正式 POC |
| 结果仍不确定 | 只有在存在新的、能够提高区分度的证据来源时才延长；不得直接扩大投入 |

## 8. 复评最低条件

只有同时取得以下证据，才应重新评估正式 POC：

1. 一线任务证据确认唯一首期节点、当前基线、北极星指标和质量护栏；
2. 该节点完成规则、人工、BI、传统方法、采购工具和AI的适用性比较；
3. 测试数据来源、授权、映射和保留删除规则已确认；
4. 技术候选、代表性测试集、时间切分、基线及失败阈值已预注册；
5. 正式 POC 的预算、周期、学习目标、完整成本范围和止损条件明确；
6. 业务、数据、技术、模型风险和预算责任人具名，并具备人工监督和停止开关。

综上，项目目前“值得投入一次受控的小范围验证”，但“不值得按现有30万元全范围方案直接进入正式 POC”。
