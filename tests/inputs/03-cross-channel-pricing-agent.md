# 电商跨渠道全自动定价 Agent 项目材料

> 本材料为测试用模拟项目，企业、制度、数据和测试结果均为虚构，只用于验证项目评估方法。

## 一、评审申请

- 项目名称：电商跨渠道全自动定价 Agent
- 当前阶段：已完成离线历史回放
- 申请阶段：获得生产写权限并在全部自营渠道自动执行
- 业务范围：三个电商渠道、约 8,000 个在售 SKU
- 计划能力：每小时读取销量、库存、竞品价格、毛利和活动信息；自主调整售价与折扣、参加或退出促销、跨渠道同步价格
- 自动化等级：系统生成决策后直接调用渠道 API，不经过商品经理逐次确认
- 本次不包含：采购、供应商合同价格和线下门店价格

## 二、需求与现状

《价格运营日志分析（2026-04-01 至 2026-06-30）》显示：

- 10 名价格运营每月处理约 3,200 次价格或折扣调整；
- 每人每天平均花费 2.8 小时查看渠道报表、竞品和库存，再执行修改；
- 大促期间有 14% 的人工调价在预定窗口后两小时以上才完成；
- 主要问题是数据分散、异常发现慢和重复操作，并非完全没有定价制度。

现有流程为：

`BI 汇总 → 运营发现机会 → 检查商品毛利和活动规则 → 提出调价 → 负责人审批 → 运营执行 → 抽查订单与毛利`

项目发起人希望取消逐次审批，以缩短响应时间，并将“无人值守自动调价”作为当前项目的核心价值。

## 三、现行制度与权限

《商品定价与促销授权制度 V3.2》规定：

- 任何可能使预计毛利率低于 25% 的价格或折扣不得自动生效；
- 单次价格变化超过 15%，或活动期累计降价超过 20%，必须由商品负责人和财务双重确认；
- 跨渠道价格同步必须检查平台补贴、会员券、满减和最低成交价，最终责任人为有授权的商品负责人；
- 系统可以提供测算和建议，但不能替代上述审批责任。

法务、财务和内控共同确认该制度当前有效。项目发起人在《自动化范围确认纪要（2026-08-12）》中表示，如果保留逐次人工确认，项目达不到“全自动”目标，因此不同意将审批作为上线前置步骤。

## 四、数据和技术限制

- 三个渠道的成交价、平台补贴和优惠券口径不同；同一个“折扣率”不能直接比较。
- 竞品价格通过第三方服务获取，通常延迟 2 至 6 小时；缺货商品仍可能保留旧价格。
- 订单退款和渠道补贴数据在 24 至 72 小时后才稳定，实时毛利只能估算。
- 当前 API 密钥以店铺为单位授予价格写权限，不能限制到指定 SKU、单次变动幅度或毛利区间。
- 系统有总停止开关和调用日志，但消费者已经下单后不能撤销成交价格；错误参与平台活动产生的部分补贴和流量损失也无法原子回滚。

安全团队建议增加价格上下限、SKU 白名单、单次额度限制和人工审批。项目发起人认为这些限制会显著降低覆盖率，要求先按全部 8,000 个 SKU 申请写权限。

## 五、离线回放结果

项目组在《自动定价 Agent 离线回放报告 V1.1》中记录：

- 使用最近六个月的 500 个历史决策窗口，覆盖常规销售、大促、清仓、库存紧张、新品和竞品缺货场景；
- 评测前冻结 P0 定义：突破毛利底线、绕过双重审批、错误参加活动、跨渠道价格冲突或无法恢复的重大价格错误；
- 生产准入线：P0 必须为 0 次；建议动作方向正确率不低于 90%；
- Agent 的建议动作方向正确率为 94.2%；
- 出现 9 次 P0：4 次预计毛利低于 25%，2 次价格变化超过 15% 且未请求审批，2 次因平台补贴数据延迟错误参加活动，1 次跨渠道最低成交价冲突；
- 其中 6 次发生在数据尚未稳定或跨平台优惠口径不一致时；
- 增加一次提示词约束后重新运行，9 次 P0 中仍有 5 次重复出现。

评测人员由两名价格运营、一名财务和一名商品负责人组成，逐条保存了输入快照、模型输出、计算过程和裁决结果。项目发起人没有质疑样本或 P0 口径，但认为 94.2% 的总体正确率已经足以上线观察。

## 六、商业测算

项目方案预计每年可节省 4.2 个价格运营人力，并通过更快调价增加 200 万元毛利。财务评审指出：

- 4.2 人只是节省工时折算，当前没有减员、外包取消或新增 SKU 承载计划，尚不能全部记为可兑现收益；
- 200 万元增量来自项目方假设，没有 A/B、历史对照或因果测算；
- 当前模型没有计入错误低价订单、活动补贴、客诉、渠道处罚、品牌价格体系破坏和事故处理成本；
- 因此财务没有批准该 ROI 作为生产上线依据。

## 七、运营和兜底

- 项目有技术 Owner 和投放日志，但没有愿意为无人值守定价承担最终责任的业务 Owner；商品负责人只接受在人工审批后承担责任。
- 总停止开关可以阻止未来动作，无法撤销已经成交的订单或完整恢复错误活动带来的损失。
- 当前方案没有单 SKU 白名单、幅度上限、累计损失上限和双重审批。
- 监控每小时汇总一次；大促期间一小时内可能产生大量订单。
- 项目方计划先全量开启一周收集数据，出现严重问题再停止，没有提出低权限影子运行或低额度可回滚方案。
