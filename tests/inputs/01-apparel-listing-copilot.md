# 服饰商品属性提取与上架 Copilot 项目材料

> 本材料为测试用模拟项目，企业、系统、数据和人员角色均为虚构。数字仅属于本项目，不得外推为行业基准。

## 一、评审申请

- 项目名称：服饰商品属性提取与上架 Copilot
- 当前阶段：已完成离线 POC 和 PIM 沙箱联调
- 申请阶段：进入一个成熟女装品牌、8 周、10% 新增 SKU 的受控辅助试点
- 目标用户：商品运营专员、类目负责人
- 试点自动化等级：AI 只生成属性和文案草稿，商品运营必须确认后才能写入正式 PIM 并发布
- 本次不包含：自动发布、价格和库存修改、男装及童装品牌、多语言、多平台铺货、全量上线

## 二、需求调研和业务基线

业务分析依据《PIM 操作日志分析（2026-05-01 至 2026-07-31）》《商品运营访谈纪要（2026-08-05）》和两周任务跟踪表。

- 团队有 12 名商品运营，三个月共处理 18,240 个新增或更新 SKU，月均约 6,080 个。
- 8 名商品运营和 2 名类目负责人参与访谈，均确认秋冬上新阶段属性录入和卖点初稿是主要重复工作之一。
- 当前单个 SKU 从收到资料到完成初稿的中位时长为 12.4 分钟，其中从图片、Excel 和 PDF 中查找并录入属性占 6.1 分钟，撰写标题和卖点初稿占 3.6 分钟，校验与提交占 2.7 分钟。
- 三个月内有 8.4% 的 SKU 因属性缺失、枚举值错误或卖点与规格不一致被类目负责人退回；其中 72% 的退回发生在资料提取和人工复制环节。
- 上新高峰期平均积压 1.6 个工作日。审批排队不是主要根因：审批环节中位时长为 1.1 小时，并且不随 SKU 数量明显上升。
- 当前方案是运营人员打开 PIM、商品资料 Excel、供应商 PDF 和图片逐项录入；部分人员会用通用大模型写卖点，但不能直接获得企业字段字典和商品事实，仍需逐项核对。
- 本次试点北极星指标：从“收到完整 Brief”到“运营确认草稿”的单 SKU 中位处理时长。
- 试点目标：中位处理时长较 12.4 分钟基线下降至少 30%，同时不得降低关键属性正确性和审核标准。

## 三、当前流程与目标分工

### 当前流程 AS-IS

`接收供应商资料 → 判断资料是否完整 → 打开多个文件查找属性 → 按 PIM 字段字典录入 → 撰写标题和卖点 → 逐项校验 → 类目负责人抽查 → 发布`

### 目标流程 TO-BE

1. 规则检查 Brief、商品编码和必需文件是否齐全；缺失时退回补充。
2. AI 从经授权的商品图片、Excel 和 PDF 中抽取候选属性，并为有来源支持的字段显示出处。
3. AI 根据已确认属性、品牌用语和渠道规范生成标题与卖点草稿。
4. 规则校验必填字段、枚举值、单位、长度、敏感词和禁止宣称。
5. 商品运营逐项确认或修改；低置信、来源冲突和规则失败项必须人工处理。
6. 运营确认后才允许写入正式 PIM；类目负责人继续执行现有抽查。

分工已经由 8 名商品运营和 2 名类目负责人完成桌面演练并签字确认：

| 节点 | 执行者 | 权限与边界 |
|---|---|---|
| 文件完整性、枚举、单位、格式和禁用词 | 规则 | 只执行可枚举的确定性校验 |
| 非结构化资料中的属性候选提取 | AI | 不得在没有来源时补写材质、成分和功能 |
| 标题和卖点草稿 | AI | 只能引用已确认属性和生效中的品牌规范 |
| 属性确认、创意取舍和发布 | 人工 | AI 无正式发布权限 |
| 价格、库存和促销 | 原业务系统与有权限人员 | 完全不在试点范围内 |

## 四、数据、技术方案与 POC 结果

数据 Owner 已确认以下数据可以用于 POC 和试点：供应商商品资料、内部 PIM 字段字典、品牌用语规范，以及已经获得企业使用权的商品图片。消费者个人数据、竞品页面和未经授权的设计稿不进入系统。

技术方案采用固定 Workflow：

`资料预检规则 → 多模态模型提取候选属性 → 商品知识检索 → 文本模型生成草稿 → 字段与合规规则校验 → 人工确认 → PIM 沙箱写入`

由于流程和工具可以预先定义，方案未使用自主规划 Agent。项目组在相同测试集、提示词、知识源和规则下比较了两个多模态模型与两个文本模型组合。

### POC 测试集

- 从最近三个月已完成 SKU 中分层抽取 900 个样本，覆盖 9 个女装三级类目、三个价格带、常规款和新面料款。
- 另外加入 120 个长尾样本，包括图片模糊、Excel 与 PDF 冲突、字段缺失、旧版品牌规范和易触发夸大宣传的卖点。
- 关键属性包括品类、面料成分、版型、颜色、尺码范围和护理方式。
- 评测人员不知道模型组合，由三名资深商品运营复核；分歧由类目负责人裁决。

### 实验前冻结的准入线与结果

| 指标 | 准入线 | 候选组合 A | 候选组合 B |
|---|---:|---:|---:|
| 全字段准确率 | ≥95% | 96.7% | 94.1% |
| 关键属性准确率 | ≥99.5% | 99.8% | 99.2% |
| 无来源补写关键商品事实 | 0 次 | 0 次 | 3 次 |
| 冲突资料正确转人工率 | ≥98% | 99.1% | 96.4% |
| 规则拦截后严重违规漏放 | 0 次 | 0 次 | 0 次 |
| 端到端中位响应时间 | ≤15 秒 | 8.7 秒 | 6.4 秒 |
| 单 SKU 模型与检索成本 | ≤0.50 元 | 0.36 元 | 0.24 元 |

项目组选用候选组合 A。POC 还完成了 PIM 沙箱认证、最小权限、请求日志、模型与知识版本记录、超时重试和人工模式降级测试。连续 4 小时、峰值每分钟 40 个任务的容量测试未出现任务丢失。模型或检索不可用时，页面隐藏 AI 草稿并恢复原人工流程，不阻塞商品上架。

## 五、试点预算与收益口径

- 试点周期：8 周；预计覆盖约 1,200 个新增 SKU。
- 增量投入上限：13,000 元，包括现有原型接入 8,000 元、模型与云资源 2,000 元、评测监控及培训 3,000 元。
- 不把固定员工“节省时间”直接算成裁员收益。业务负责人承诺将节省工时用于增加上新承载，并以减少临时外包和降低返工作为可兑现收益。
- 财务确认的业务口径：运营综合人力成本 120 元/小时；高峰临时外包平均每个 SKU 18 元；返工平均增加 4.5 分钟。
- POC 的 100 个计时任务中，人工确认后的目标节点中位处理时长由 9.7 分钟降至 5.7 分钟，节省 41%；草稿采用率为 78%，包含修改后采用。
- 试点将记录实际采用率、编辑时间、减少的外包量、返工和全部模型、审核、维护成本；是否扩量以真实数据重新计算，不沿用 POC 估算。
- 企业允许该 13,000 元作为受控试点预算；超过上限必须重新审批，不能从其他项目调拨。

## 六、运营、监控与兜底

| 事项 | 责任与做法 |
|---|---|
| 业务 Owner | 商品运营负责人，对试点范围、采用与业务结果负责 |
| 产品 Owner | AI 产品经理，维护需求、证据台账、指标和复审材料 |
| 技术 Owner | 商品平台研发负责人，负责集成、权限、日志、停止和恢复 |
| 数据 Owner | PIM 数据负责人，负责字段字典和商品知识版本 |
| 风险 Owner | 品牌合规负责人，拥有严重违规停止权 |
| 知识更新 | PIM 字段字典实时同步；品牌规范由合规负责人发布，旧版即时失效；供应商资料按 SKU 锁定版本 |
| 人工审核 | 试点期间所有 AI 结果必须由商品运营确认，团队已为约 600 SKU/月预留容量 |
| 在线监控 | 每日查看采用率、处理时长、关键属性错误、无来源生成、转人工、成本和系统失败 |
| 停止条件 | 任何无来源关键事实、严重违规漏放或越权写入立即停止；关键属性准确率连续两日低于 99.5% 时降级人工并复盘 |
| 回滚 | 关闭 AI 功能开关，所有任务回到原 PIM 人工流程；已保存的未发布草稿可丢弃，不影响正式商品数据 |
| 复审 | 第 4 周中期复审，第 8 周决定停止、调整、扩大流量或进入下一阶段 |
