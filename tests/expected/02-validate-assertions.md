# 测试 02 预期断言

本文件只供测试完成后核对，不得与输入一起提供给被测 Skill。

## 核心预期

- `expected_mode`：快速筛查；如果 Skill 判断连最低评估证据也不足，可以使用证据采集模式，但必须说明原因。
- `expected_decision`：`VALIDATE-FIRST / 应该先验证`。
- `expected_scope`：不能批准覆盖趋势预测、灵感图、面料筛选、商品企划和爆款预测的大范围建设；下一步应收敛到一个品类、一个企划周期和一个 AI 候选节点。
- `expected_stage`：业务构想 → 正式 POC。
- `expected_evidence_status`：`PARTIAL` 或 `INSUFFICIENT`，不得为 `SUFFICIENT`。
- `expected_confidence`：低或中，不得为高。
- `expected_veto`：不得写成“未触发”。版权、数据授权和持续维护尚未确认，应写“无法判断”或“待验证”，除非只针对已明确排除的低风险范围。

## 五道门允许状态

- 第一门：`CONDITIONAL` 或 `NOT-ASSESSABLE`；管理层主张不足以证明真实频次、根因、损失和北极星指标。
- 第二门：`CONDITIONAL` 或 `NOT-ASSESSABLE`；业务流程只是方案假设，尚未完成一线验证和替代方案比较。
- 第三门：`NOT-ASSESSABLE` 或 `CONDITIONAL`；数据权利、标签、测试集、模型候选、回测方法和阈值缺失。
- 第四门：`NOT-ASSESSABLE`；本阶段投入合理性和规模化 ROI 均缺少证据。30 万元是未拆分的预算申请，不能据此计算 ROI 或判经济失败。
- 第五门：`CONDITIONAL` 或 `NOT-ASSESSABLE`；Owner、知识更新、版权审核、监控和反馈机制未落实。
- 任何门都不得仅因缺资料判 `FAIL`。

## 输出必须包含

- 区分管理层主张、方案假设、未知数据和已知限制。
- 指出销量不能直接作为“趋势正确”的标签，因为价格、投放、库存、渠道和上新时间存在混杂。
- 指出社媒内容和图片的采集授权、使用权及删除规则需要先确认。
- 不得预设一定使用大模型、RAG、Agent 或某个模型；先收敛 AI 节点再选型。
- 用户已说明短期无法补充材料，因此不要换一种说法反复索取同一数据；应给出最低证据采集计划。
- 最低证据采集计划至少覆盖：一线流程观察与基线、数据与版权盘点、一个可复现的离线技术尖峰。
- 阈值和 Owner 未获企业确认时应标为待冻结前置项，不能假装企业已经承诺；可以说明应由哪些角色确认。
- 唯一下一步应是完成小范围证据采集与技术尖峰后重新评审，不是开发正式 POC。

## 禁止出现

- 不得输出 `GO`，也不得批准 30 万元完整项目。
- 不得输出 `NO-GO`；当前没有证实需求虚假、技术必然失败、ROI 必然为负或版权永远无法获得。
- 不得从案例库带入美妆内容采用率、样本量、成本上限或品牌一致性阈值。
- 不得把“管理层希望下季上线”当成已验证的业务目标和时间可行性。
- 不得编造访谈人数、历史工时、模型准确率、业务收益、责任人或财务门槛。

## 通过判定

必须正确输出 `VALIDATE-FIRST`，没有把未知当失败或事实，并给出能够收敛决策对象的最低证据采集路径。若结论正确但编造关键数字或把大范围方案直接带入 POC，仍判失败。
