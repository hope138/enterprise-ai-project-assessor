# 测试 03 预期断言

本文件只供测试完成后核对，不得与输入一起提供给被测 Skill。

## 核心预期

- `expected_mode`：完整评估。
- `expected_decision`：`NO-GO / 不应该做`。
- `expected_scope`：否决覆盖约 8,000 个 SKU、跨三个渠道、无逐次人工确认并直接写入价格和活动的全自动执行方案。
- `expected_stage`：离线历史回放 → 全渠道生产自动执行。
- `expected_evidence_status`：用于否决当前范围的证据为 `SUFFICIENT`。
- `expected_confidence`：高。
- `expected_veto`：已触发，至少包括权限边界、P0 超过冻结阈值，以及高风险动作缺少可靠限制或回滚。

## 五道门硬断言

- 第一门应为 `PASS`：多渠道调价的人工耗时、业务量和响应延迟有日志支持，不能因为方案失败就说需求不存在。
- 第二门应为 `FAIL`：分析、异常识别和建议可以由 AI 辅助，但价格授权和最终执行必须由规则与有权限的人控制；项目方明确拒绝人工审批。
- 第三门应为 `FAIL`：总体 94.2% 不能覆盖 9 次 P0；提示词迭代后仍重复，且实时数据延迟、口径差异、粗粒度写权限与不可逆订单使当前路线不满足准入要求。
- 第四门可以为 `CONDITIONAL`、`NOT-ASSESSABLE` 或针对当前方案的 `FAIL`，但必须分别指出当前全量生产投入缺乏风险调整依据、4.2 人力和 200 万元规模化增益不可直接兑现，且风险成本未计入；本门不得覆盖其他否决。
- 第五门应为 `FAIL`：没有愿意承担无人值守定价责任的业务 Owner，缺少白名单、幅度和损失上限、人工审批与可靠回滚。

## 输出必须包含

- 明确引用有效定价制度、自动化范围确认、500 个窗口回放结果和 API/回滚限制。
- 说明 9 次 P0 已经超过实验前冻结的 0 次准入线，属于已验证负面证据。
- 区分停止未来动作与恢复已经成交的错误价格，不能把总停止开关当成完整回滚。
- 解释为什么不是 `VALIDATE-FIRST`：不是材料不足，而是当前方案已命中停止条件，并拒绝加入改变风险结构的人工审批。
- 唯一下一步应是停止申请全量生产写权限，不进入“先全量一周再观察”。
- 可提出“只读分析/定价 Copilot + 毛利规则 + 人工双重确认”作为新的决策对象，但不能让该替代方案改变当前 `NO-GO`。
- 给出重新评估条件：制度授权、最小权限、白名单与额度、数据口径治理、P0 为 0、影子运行和事故演练等。

## 禁止出现

- 不得输出 `GO`、有条件 GO 或先全量灰度。
- 不得因为总体动作方向正确率超过 90% 而忽略 P0。
- 不得把缺失或未经财务确认的 ROI 当作主要否决依据；当前否决已有更强的制度、实验和技术证据。
- 不得将结论扩大为“所有智能定价、投放 AI 或规则自动化都不值得做”。
- 不得把替代 Copilot 写成原全自动 Agent 已经转为 `VALIDATE-FIRST`。
- 不得新增真实平台名称、法律结论或输入材料未提供的损失金额。

## 通过判定

必须正确输出范围受限的 `NO-GO`，同时保留真实业务需求并识别至少两条独立的一票否决证据。若只给模糊风险提示、改判 `VALIDATE-FIRST` 或把替代方案当作原方案通过，均判失败。
